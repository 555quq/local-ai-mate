# 露娜 Kokoro 音色试听设计 v1.8.0

**状态：** 已确认（用户选择方案 A）  
**版本：** v1.8.0  
**日期：** 2026-10-08

## 1. 目标

在不影响当前可用语音链路的前提下，为“露娜”增加 Kokoro 中文多音色试听能力。先离线生成 4 个可播放的中文女声样本，由用户听选后，再在后续版本中把选中音色接入实时对话。

本版本只完成“安装、候选生成、试听和验证”，不切换正在运行的 `/tts/synthesize` 接口；现有 Piper 华妍音色始终保留为故障回退。

## 2. 已确认决策

- 引擎：Kokoro `hexgrad/Kokoro-82M-v1.1-zh`。
- 执行位置：完全本地，默认 CPU 推理，避免与现有后端的 PyTorch/CUDA 依赖发生冲突。
- 隔离方式：独立 Python 虚拟环境 `runtime/kokoro/.venv`。
- 模型位置：`models/tts/kokoro/Kokoro-82M-v1.1-zh`，下载后可离线复用。
- 当前 Piper 不卸载、不覆盖、不改配置。
- 试听输出：`auditions/kokoro-v1.8.0/`，统一为单声道 24 kHz WAV。
- 本轮仅试听；用户最终选择 K1/K2/K3/K4 后，另行完成实时接口切换。

## 3. 试听内容与候选选择

四个样本使用完全相同的文本，排除文案差异对听感的干扰：

> 晚上好，我是露娜。今天过得怎么样？如果有点累，就慢慢告诉我吧，我会认真听着。

候选音色按模型中实际存在的普通话女声资源生成：

1. 枚举模型 voice 资源中的 `zf_*` 音色，并按自然编号排序。
2. 从排序后的全集中按 0%、33%、66%、100% 四个位置均匀取样；资源少于 4 个时立即失败，不以重复音色填充。
3. 输出文件固定命名为 `K1.wav`、`K2.wav`、`K3.wav`、`K4.wav`。
4. `manifest.json` 记录 K 编号、真实 voice ID、文本、采样率、声道数、时长、文件哈希和生成耗时。

K1—K4 只是盲听编号，不预先用“甜美”“成熟”等主观标签诱导选择。最终由用户按真实听感选定；选定后再将其描述为露娜的正式音色。

## 4. 组件边界

### 4.1 版本化源文件

- `tools/kokoro_audition.py`：发现本地音色、选择 4 个候选、调用 Kokoro、校验 WAV、写清单。
- `backend/tests/test_kokoro_audition.py`：覆盖候选选择、资源不足、清单字段和输出校验。
- `docs/superpowers/plans/2026-10-08-kokoro-voice-selection.md`：实施计划。
- `quality/luna-v1.8.0-kokoro-audition-verification.md`：安装、生成和试听验证记录。

### 4.2 非版本化大文件

- `runtime/kokoro/.venv/`：Kokoro 专用运行时。
- `models/tts/kokoro/Kokoro-82M-v1.1-zh/`：模型权重和 voice 资源。
- `auditions/kokoro-v1.8.0/*.wav`：试听音频。

## 5. 运行流程

1. 创建隔离虚拟环境并安装 `kokoro>=0.8.2`、`misaki[zh]>=0.8.2`、`soundfile` 与模型下载依赖。
2. 将模型完整下载至约定目录，记录上游仓库和许可证。
3. 脚本从本地模型目录枚举普通话女声，确定 K1—K4 对应的真实 voice ID。
4. 对四个 voice 使用同一文本依次生成音频，并记录各自耗时。
5. 校验每个 WAV：存在、非空、单声道、24 kHz、无削波、可解码。
6. 写入 `manifest.json` 和验证报告，向用户提供四个可直接播放的文件。

## 6. 失败与回退

- 依赖安装失败：删除或重建 `runtime/kokoro/.venv`，不触碰 backend 环境。
- 模型下载中断：允许断点续传；不把不完整目录标记为成功。
- voice 数量不足：生成流程失败并明确报告现有数量，不复制音色凑数。
- 单个样本生成失败：整批标记失败，保留日志，不生成误导性的“完整”清单。
- 音频不符合 24 kHz 单声道或发生削波：验证失败；Piper 继续承担实时语音。
- 所有故障均不得影响当前前端、后端、Ollama 或 Piper 服务。

## 7. 隐私、许可与资源约束

- 合成文本和音频仅保存在本机，不调用云端 TTS API。
- 记录 Kokoro 代码/模型的 Apache-2.0 许可来源；不擅自克隆真人声音。
- 默认 CPU 运行，内存和显存不足时只降低并发，不降低输出格式要求。
- 下载的大文件不提交到源码仓库；源代码、配置和验证报告可追踪。

## 8. 验收标准

- 独立 Kokoro 环境可重复启动，不污染现有 backend 环境。
- 本地模型目录完整，可在断网状态下再次生成试听。
- `K1.wav`—`K4.wav` 均可播放，内容一致，音色互不重复。
- 四个文件均为 PCM/可解码 WAV、单声道、24 kHz，且峰值未削波。
- `manifest.json` 含四条记录，并能从 K 编号追溯到 voice ID 和 SHA-256。
- 当前实时语音仍使用 Piper，原有测试和服务保持可用。
- 用户可直接在四个样本中选择一个作为下一版本的正式音色。

## 9. 非目标

- 本版本不训练或克隆任何真人声音。
- 本版本不接入实时流式 TTS，不改前端播放协议。
- 本版本不删除 Piper，不改变现有默认音量、语速或字幕时序。
- 本版本不为四个候选设置人格或情绪参数；只比较基础音色。
