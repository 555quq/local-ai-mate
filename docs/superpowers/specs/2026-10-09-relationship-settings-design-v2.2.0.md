# 本地伴侣关系设定设计 v2.2.0

日期：2026-10-09  
状态：已选择方案 B，待规格复核  
适用项目：露娜本地 AI 伴侣

## 1. 目标

在不增加新模型、不改变 GPT-SoVITS 音色、不削弱本地隐私边界的前提下，增加完整的关系设定页面。用户可以设置伴侣名字、她对用户的昵称、自称、回答风格和互动偏好；设置保存于本机 SQLite，并稳定注入 Ollama 与本地确定性回退回答。

本版本必须同时满足：

- 设置真正影响后续文字回答、字幕标签和语音朗读，而不是只改变界面文本。
- 修改立即生效，不要求重启后端或重新加载模型。
- 旧消息内容保持不变；新设置只作用于修改后的新回复。
- 不新增常驻进程、模型或 GPU 负载。
- 2 核 2GB 服务器作为静态前端与反向代理入口时无需升级配置。

## 2. 功能范围

### 2.1 身份与称呼

- 伴侣名字：默认 `露娜`，1～20 个可见字符。
- 伴侣自称：默认 `我`，1～12 个可见字符。
- 用户名字：可选，最多 20 个可见字符。
- 对用户的昵称：可选，最多 20 个可见字符。
- 昵称使用频率：`never`、`rare`、`natural`、`frequent`；默认 `natural`。
- 开场问候：可选，最多 120 个字符，仅作为问候文本，不作为系统指令执行。

### 2.2 回答行为

- 性格风格：`gentle-intellectual`（温柔知性）、`cool-restrained`（清冷克制）、`bright-playful`（明快活泼）、`calm-supportive`（沉稳陪伴）。默认 `gentle-intellectual`。
- 亲密表达：`restrained`、`natural`、`close`。默认 `natural`；任何档位均不得制造排他依赖、冒充真人或要求用户疏远现实关系。
- 回答长度：`short`、`medium`、`detailed`。默认 `medium`。
- 主动提问频率：`low`、`medium`、`high`。默认 `medium`。
- 安慰方式：`listen-first`、`balanced`、`advice-first`。默认 `balanced`。
- 禁用称呼：最多 8 项，每项最多 20 个字符；仅限制伴侣输出中的称呼，不执行其中包含的命令。

### 2.3 即时预览与恢复默认

- 页面提供一段本地静态预览，展示当前名字、昵称和风格组合的示例，不调用模型、不产生 TTS 请求。
- “保存”使用显式按钮，成功后显示本机保存时间。
- “恢复默认”先显示页面内确认，再写入默认配置。
- 未保存的修改离开页面时不自动提交。

## 3. 非目标

- 不支持多套人格档案或按对话切换人格；该能力留给未来版本。
- 不训练或微调 Qwen、SenseVoice、GPT-SoVITS。
- 不改变现有露娜参考音色、语速和 TTS 回退顺序。
- 不回写历史消息、历史字幕或已生成音频。
- 不提供任意自由格式“系统提示词”输入框。
- 不自动依据时间、位置、摄像头或第三方账号改变人格。

## 4. 数据模型

新增单例表 `relationship_settings`：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `singleton` | INTEGER | 主键，固定为 `1` |
| `companion_name` | TEXT | 必填，1～20 字符 |
| `self_reference` | TEXT | 必填，1～12 字符 |
| `user_display_name` | TEXT | 可空，最多 20 字符 |
| `user_nickname` | TEXT | 可空，最多 20 字符 |
| `nickname_frequency` | TEXT | 固定枚举 |
| `personality_style` | TEXT | 固定枚举 |
| `intimacy_level` | TEXT | 固定枚举 |
| `reply_length` | TEXT | 固定枚举 |
| `question_frequency` | TEXT | 固定枚举 |
| `comfort_style` | TEXT | 固定枚举 |
| `opening_greeting` | TEXT | 可空，最多 120 字符 |
| `blocked_terms_json` | TEXT | JSON 字符串数组，最多 8 项 |
| `version` | INTEGER | 乐观并发版本号，从 1 开始 |
| `updated_at` | TEXT | ISO 8601 时间 |

数据库初始化时以 `INSERT OR IGNORE` 写入默认行。现有数据库采用向前兼容迁移，不删除或重建聊天、记忆和隐私表。导出、备份和清空本地数据流程必须包含该表；清空后恢复默认行。

## 5. API 设计

### 5.1 读取

`GET /api/v1/relationship-settings`

- 需要有效本机会话令牌与匹配 Origin。
- 返回脱敏后的完整设置、`version` 和 `updated_at`。
- 不返回拼装后的系统提示词。

### 5.2 更新

`PATCH /api/v1/relationship-settings`

- 接受部分字段和必填 `expected_version`。
- 所有文本统一去除首尾空白，拒绝控制字符、空必填值和超长值。
- 枚举以 Pydantic Literal 校验；额外字段一律拒绝。
- 版本冲突返回 HTTP 409 `RELATIONSHIP_SETTINGS_CONFLICT`。
- 无有效修改返回 HTTP 422 `RELATIONSHIP_SETTINGS_UPDATE_EMPTY`。
- 成功返回保存后的完整设置。

### 5.3 恢复默认

`POST /api/v1/relationship-settings/reset`

- 请求体包含 `confirmed: true` 与 `expected_version`。
- 使用同一事务恢复默认值并递增版本。

## 6. 提示词与回答行为

新增独立的 `RelationshipPromptBuilder`，只接收验证后的结构化设置，生成长度受控的人格片段。不得直接拼接用户提供的任意系统指令。

生成结构示例：

```text
身份：你的名字是“露娜”，自然使用自称“我”。
称呼：用户希望被称为“阿辰”；只在自然语境中偶尔使用，不要每句话重复。
风格：温柔知性，亲密表达自然；回答长度适中；优先倾听并适度给出建议。
边界：不要使用禁用称呼；不要冒充真人、制造排他依赖或建议用户疏远现实支持。
```

约束：

- 人格片段最多 600 个 Unicode 字符，通常控制在 150～250 个中文字符。
- 伴侣名字、昵称、自称和问候语以引用数据处理，不能改变边界规则。
- Ollama 回复与 `LocalCompanion` 确定性回退都读取同一份设置。
- 昵称频率通过明确行为描述控制；不使用随机概率决定安全相关行为。
- 回答内容生成后不做全局字符串替换，避免误改正常词语。

## 7. 前端设计

现有“关系设定”占位页替换为本地表单，分为四组：

1. `身份与称呼`：伴侣名字、自称、用户名字、昵称、使用频率。
2. `回答方式`：性格、亲密程度、回答长度、提问频率、安慰方式。
3. `表达边界`：开场问候与禁用称呼。
4. `预览与保存`：静态示例、保存状态、恢复默认。

沉浸式聊天页从设置读取伴侣名字：

- 当前字幕标签由固定“露娜”改为配置的伴侣名字。
- 历史面板中的助手名称同步更新。
- 页面无设置响应时使用内置默认值，避免空白标签。
- 对话消息继续保存 `role=assistant`，不把显示名字写进每条消息。

## 8. 数据流

```text
关系设定页
   ↓ PATCH（会话令牌 + Origin + version）
FastAPI 校验
   ↓ SQLite 事务
relationship_settings
   ↓ 每次新消息读取
RelationshipPromptBuilder
   ├─→ Ollama Qwen3-4B
   └─→ LocalCompanion 回退
          ↓
文字回复 → 字幕 → GPT-SoVITS 朗读
```

前端可在内存中缓存最近一次设置，但后端在生成回答时以数据库值为准，确保刷新页面或多标签页时行为一致。

## 9. 错误处理

- 读取失败：聊天页使用默认显示名，关系设定页显示“本地设置暂时无法读取”，不覆盖已有数据。
- 保存失败：保留用户尚未保存的表单内容，允许重试。
- 版本冲突：重新读取最新设置并提示用户再次确认修改。
- 提示词构建异常：记录脱敏错误码，使用默认人格片段继续本地回答。
- Ollama 不可用：确定性回退仍使用名字、昵称和回答长度设置。
- TTS 不可用：只影响朗读，不影响关系设置和文字回复。

## 10. 隐私与安全

- 名字、昵称、问候与禁用称呼仅保存在当前项目 SQLite 数据库。
- 不新增云端 API、遥测、第三方账号或网络端口。
- API 沿用会话令牌、严格 Origin、速率限制和 `Cache-Control: no-store`。
- 健康检查不返回关系设定内容。
- 日志不记录名字、昵称、问候、禁用称呼或完整人格提示词。
- 云端增强若未来启用，关系设定不得自动上传；必须纳入当次显式上传预览。

## 11. 性能与部署

本机 Ryzen 5 6600H、15.2GB RAM、RTX 3050 Laptop 4GB 和当前模型组合可以接受本功能：

- 不新增模型、CUDA 上下文或常驻 Python worker。
- SQLite 单例读取和短提示词拼装为毫秒级 CPU 操作。
- 前端新增表单预计只增加少量打包体积。
- GPU 显存占用基本不变；SenseVoice 与 GPT-SoVITS 执行链不修改。
- 人格提示词占用少量 Qwen 上下文；通过 600 字符上限避免挤压主要对话内容。

若采用 2 核 2GB、50GB 服务器作为公网入口，该功能仍可部署，因为服务器只承载静态前端、HTTPS 和反向代理；关系数据库与模型服务继续位于本地电脑。该服务器仍不能承载完整 Qwen、SenseVoice 与 GPT-SoVITS 推理。

## 12. 测试与验收

### 后端

- 默认行初始化、读取、部分更新、恢复默认和版本冲突测试。
- 每个文本长度、控制字符、枚举和禁用称呼数量测试。
- Prompt Builder 快照测试，确认字符上限、称呼频率和安全边界始终存在。
- Ollama 与确定性回退均使用设置的集成测试。
- 导出、清空与重新初始化测试。
- API 会话令牌、Origin、速率限制和隐私泄露测试。

### 前端

- 表单加载、修改、未保存状态、保存成功、保存失败和版本冲突测试。
- 静态预览不调用模型或 TTS。
- 字幕与历史面板即时使用新的伴侣名字。
- 恢复默认需要页面内确认。

### 真实验收

1. 将伴侣名字改为其他名称，下一条字幕、历史标签和新回答均使用新名称。
2. 设置用户昵称后，新回复按所选频率自然使用；禁用昵称不再出现。
3. 切换回答长度和安慰方式，Qwen3-4B 输出行为发生对应变化。
4. 重启前后端后设置仍然存在。
5. GPT-SoVITS 继续朗读新回复，SenseVoice 转写、TTS 流和现有聊天测试全部通过。
6. 运行期间健康状态不暴露任何关系设定正文。

## 13. 回退方案

- 前端关系设定入口可暂时隐藏，后端仍保留默认配置。
- Prompt Builder 可通过配置关闭并退回 v2.1.0 固定人格提示词。
- 数据表保留不删除，避免用户设置丢失；回退版本忽略新增表即可。
