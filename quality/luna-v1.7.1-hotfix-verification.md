# 露娜本地伴侣 v1.7.1 热修复验证

日期：2026-10-08  
范围：文字发送延迟、麦克风授权后无响应

## 根因

1. React 开发模式的 StrictMode 会执行一次 `setup → cleanup → setup` 生命周期检查。语音 Hook 的 cleanup 把 `mountedRef` 设为 `false`，第二次 setup 没有恢复；用户允许麦克风后，代码误判组件已经卸载并立即停止全部音轨。
2. Ollama 每条消息都会重新请求 `/api/tags`、创建两个 HTTP 客户端，并让 Qwen3 产生约百余个不展示的思考 token；后端在模型完成前也不能返回消息。
3. 原始麦克风 RMS 阈值 `0.035` 对部分笔记本麦克风偏高。

## 修复

- Hook 每次 effect setup 显式恢复 mounted 状态，并增加 StrictMode 回归测试。
- `MediaRecorder.start(250)` 定期产生内存块，改善短语音停止时的浏览器兼容性。
- 语音阈值降为 `0.012`；音频仍不落盘。
- Ollama 复用单个 `httpx.Client`，关闭系统代理继承并缓存最近健康状态。
- Qwen3 请求使用 `think: false`、`/no_think`、`num_predict: 128`、`num_ctx: 2048`、`keep_alive: 10m`。
- 模型调用移入工作线程，避免阻塞 FastAPI 事件循环。
- 用户消息在点击发送后先进行本地乐观回显；失败时自动撤回。

## 验证结果

- 浏览器权限状态：`granted`。
- 浏览器实测点击光球：`待命 → 正在聆听`，`aria-pressed=true`，停止按钮出现。
- 浏览器实测停止：返回 `待命`，活动状态清除，停止按钮消失。
- 修复前 API 短消息：约 9.16 秒。
- 修复后 API 首条短消息：约 0.48 秒；同会话后续消息约 0.27 秒。
- 页面级乐观回显：约 0.04 秒；助手字幕：约 0.52 秒。
- 前端测试：23/23 通过。
- 后端测试：24/24 通过。
- TypeScript 与 Vite 生产构建：通过。

测试使用独立浏览器标签；验证结束后已关闭该标签并停止测试语音会话，没有占用麦克风。
